# Evidence Package

This document describes the evidence set an enterprise reviewer should expect for a release or deployment review.

## Generated Runtime Evidence Package (v1.5.0 WS3)

The runtime half of this evidence set is generated from live records by
the control plane itself, for a stated window:

```
acr evidence-package --output evidence.zip \
  --window-start <ISO 8601> --window-end <ISO 8601>
```

or `POST /acr/evidence-packages`. The package contains: a summary of
decision counts and rates (including the observe/enforce split),
agent inventory and manifests, policy release metadata active in the
window, the decision records (JSONL, plus a CSV index), approval
records, containment event history, drift samples and governed
baseline versions, observe-mode and policy-simulation summaries,
per-correlation telemetry integrity verification results, and the
framework control mapping (`control-mapping.md`, embedded). A
`MANIFEST.json` lists every file with its SHA-256, hash-chained so
entries cannot be reordered, dropped, or edited undetected, plus
generation metadata (who, when, window, version). The bundled
`verify_package.py` re-checks all of it using only the Python standard
library — no ACR installation required.

Two deliberate exclusions, also stated in the package README: retained
evaluation input **payloads are never exported** (hashes and state
only — retention redaction exists to protect them), and approval
action parameters are represented by SHA-256 rather than value.

Everything below this section is **not** generated by the runtime
package. It is supplied by the release process, the deployment, or the
operating organization, and the package README says so explicitly —
the generator does not claim to produce it.

## Core Product Evidence

- release tag and merge commit
- signed container images
- build provenance attestations
- signed compliance package tarball and checksum file
- policy release history and active bundle alias
- failure/load/DR validation report

## Runtime Governance Evidence

- sample approval records
- sample evidence bundle for a single correlation id
- telemetry integrity verification result
- drift baseline and drift score outputs
- containment event history

## Deployment Evidence

- production configuration values from a secret manager, not committed files
- OIDC and role-mapping configuration
- network policy or equivalent ingress/egress controls
- digest-pinned deployment manifest or Helm values
- backup and restore verification logs

## Security Review Evidence

- CI security scan output
- SBOM generation record
- dependency audit output
- static-analysis findings and resolution notes
- release verification record showing cosign and attestation checks

## Known Limits

Evidence generated by the product is only part of the package. Enterprise reviewers will still expect:

- identity governance records
- change approvals
- vulnerability remediation process
- incident-management process
- external assessment results
